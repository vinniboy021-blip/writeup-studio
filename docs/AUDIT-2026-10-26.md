# Auditoria técnica e de segurança — 2026-10-26

Escopo: revisão estática do commit `2274975d9ffdbe8b367da27d8e85ff92c2a5023c` da branch `main`, cobrindo API FastAPI, frontend Next.js, autenticação/RBAC, integrações, Docker Compose, CI e documentação. Esta auditoria não substitui teste de implantação em ambiente controlado.

## Achados confirmados

### A1 — CI não é reprodutível e não executa a matriz declarada (alto)

Arquivo: `.github/workflows/ci.yml`.

O job Python executa `pip install -e apps/api`, mas `pytest`, `pytest-cov`, Ruff e Pyright estão apenas no extra `dev`. O workflow não instala `apps/api[dev]` e não declara serviços PostgreSQL/Redis. Portanto, a execução de `pytest apps/api/tests` pode falhar por dependência ausente e os testes de infraestrutura não são exercitados em CI.

O job web executa apenas `npm install` e `npm run build`; não executa `npm ci`, typecheck, lint, Vitest ou Playwright.

Correção: instalar os extras de desenvolvimento, usar lockfiles, declarar serviços PostgreSQL/Redis com health checks, executar migrations, pytest com cobertura, Ruff/Pyright e, no frontend, `npm ci`, typecheck, lint e Vitest. Publicar E2E como job separado com navegador fixado.

### A2 — Artefatos de teste foram publicados no repositório (médio)

A árvore remota contém `apps/api/.pytest_cache/` e seus arquivos `lastfailed` e `nodeids`. São artefatos locais, podem expor nomes de testes/caminhos e tornam o commit não reproduzível. O `.gitignore` não protege contra o fato de eles já terem sido enviados.

Correção: remover os artefatos do histórico/branch, ampliar o filtro de publicação para caches aninhados e validar o conjunto de arquivos antes de cada release.

### A3 — Documentação Kali MCP contradiz o contrato implementado (alto para operação)

`docs/KALI-MCP.md` descreve uma chamada `exec`, comandos shell e uma allowlist de comandos. O código atual implementa ferramentas tipadas (`system_info`, `artifact_hash`, `artifact_file`, `artifact_strings`, `artifact_json_summary`) e rejeita argumentos arbitrários e comandos. Um operador seguindo a documentação pode configurar um servidor incompatível ou interpretar incorretamente o limite de segurança.

Correção: documentar o contrato `tools/list`/`tools/call`, schemas dos cinco tools, autenticação Bearer, limites de bytes, proveniência e exemplos reais do payload atual. Remover referências a execução de comandos como interface pública.

### A4 — Backup e restore não têm validação automática no CI (médio)

`scripts/backup.py` possui verificações de hash e preflight, mas o CI não executa um ciclo backup → verify → restore em PostgreSQL descartável nem valida a recuperação de objetos S3/MinIO. A documentação registra RPO/RTO como metas, porém não há evidência de execução do procedimento no pipeline.

Correção: adicionar job de integração que crie banco e storage descartáveis, execute backup, corrompa uma cópia, confirme que `verify` falha e faça restore em banco vazio. Registrar duração e resultado como artefato.

### A5 — Dependências de aplicação não estão totalmente fixadas (médio)

O backend usa intervalos `>=` no `pyproject.toml` e o frontend usa ranges `^` no `package.json`. O frontend possui lockfile, mas o CI usa `npm install`, permitindo resolução diferente do lockfile. O backend não possui lock de produção.

Correção: gerar e versionar lock de produção Python (com hashes), usar `npm ci`, configurar atualizações automatizadas e executar `pip-audit`/auditoria npm em CI.

### A6 — Observabilidade de produção depende de configuração externa não validada (baixo/médio)

`METRICS_TOKEN` é gerado vazio pelo script de setup. O Nginx de produção bloqueia a rota de métricas, o que reduz a exposição no caminho normal, mas uma publicação direta da API pode deixar métricas sem autenticação.

Correção: exigir token de métricas não vazio em produção ou desabilitar métricas HTTP e coletar por rede interna autenticada. Validar a configuração no startup.

## Pontos positivos verificados

- Sessões usam cookie HttpOnly, SameSite e token CSRF separado.
- Senhas exigem Argon2id via `pwdlib[argon2]`.
- RBAC reavalia associação atual à equipe para recursos `team`.
- Atualização de writeups usa versão esperada e cria revisão.
- MCP não aceita URL, caminho ou comando fornecido pelo usuário; a ponte usa argv fixo e `shell=False`.
- Evidências usam hash SHA-256, armazenamento privado e download autenticado.
- Produção exige PostgreSQL, HTTPS, cookies Secure, Redis para rate limit e filas.
- Nginx bloqueia documentação, readiness e métricas no perfil de produção.

## Limitações da auditoria

O ambiente de execução não ficou disponível durante a revisão, portanto não foi possível repetir localmente pytest, migrations, build Docker ou um fluxo E2E. O resultado acima é baseado na árvore GitHub e nos contratos/código publicados. Os achados A1–A5 são verificáveis diretamente nos arquivos citados; A6 depende do modo de exposição adotado pela operação.
